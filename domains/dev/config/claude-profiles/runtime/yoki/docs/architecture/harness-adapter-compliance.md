# Harness / adapter compliance matrix

Generated from `scripts/lib/harness-adapter-compliance.js`'s `ADAPTER_RECORDS`
— edit that file, not this table. Regenerate with the one-liner in the
module's header comment, and check the result in: `validateDocumentation()`
(called from `core/validation/validator.sh`) fails the build if this file
drifts from `ADAPTER_RECORDS`.

Only `codex` and `omp` are current install targets yoki actually generates
for (`yoki-switch apply --target <name>`, `runtime/yoki/scripts/lib/targets/`).
The rest of the matrix predates the 2026-08-03 split from the vendored ECC
("Everything Claude Code") upstream and is kept here as design-pressure
history rather than an active target list — `state` descriptions below still
say "ECC" for that reason.

## Compliance states

| State | Meaning |
| --- | --- |
| Native | ECC can install or verify the surface directly for this harness. |
| Adapter-backed | ECC has a thin adapter, plugin, or package surface, but parity differs by harness. |
| Instruction-backed | ECC can provide the guidance and files, but the harness does not expose the runtime hook/session surface ECC needs for enforcement. |
| Reference-only | The tool is useful as a design pressure or external runtime, but ECC does not yet ship a direct installer or adapter for it. |
