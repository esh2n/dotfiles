- [LiteLLM が応答に入れた費用を pi と omp がそのまま表示できるか](2026-09-30-server-reported-cost.md) — LiteLLM は `include_cost_in_streaming_usage: true` でストリーミングの最後の `usage.cost` に費用を入れられる（v1.103.0-rc.1 で確認）。omp はその値を読む関数を持つが provider 名が `openrouter` と `cline-pass` のときだけ（openai-shared.ts:406）、pi には読む経路が無い。DeepSeek の時間帯割引は LiteLLM の計算に無い (2026-09-30)
- [プロキシの別名で呼ぶモデルの費用を、価格表の写しを持たずにどう出すか](2026-09-30-agent-cost-method.md) — ベンダーは「費用はサーバーが計算して運ぶ」側で、LiteLLM 自身も手元に固定した価格表を劣化経路と書く。応答本文の `usage.cost` はストリーミングだけ（非ストリーミング対応の PR #41532 は未マージ）。`/spend/logs` は書き込みが 10〜15 秒遅れる（`PROXY_BATCH_WRITE_AT` 10 秒＋揺らぎ 0〜5 秒）。`/model/info` は単価を返すが、起動時に取りにいくクライアントは見つからず。pi は拡張から `registerProvider` を後から呼べるが、omp の `cost` は静的な数値だけ。価格不明は「0 でなく出さない」に aider・Cline・LiteLLM の PR が揃い、LiteLLM は黙って $0 になる件で数週間気づかれない実害を書いている (2026-09-30)
- [並列の作業役の一覧で、完了した行・トークン・費用・進み具合をどう見せているか](2026-09-30-agent-table-conventions.md) — 完了行: Claude Code は成功を即消して失敗・停止を 30 秒残す、omp は読み終えたジョブを 30 秒で消し作業役は 7 分で既定の一覧から外す（二実装が独立に 30 秒へ）、Kimi は残し続けてメモリが数百 MB 膨らみ修正した。トークン: Kimi はキャッシュ読みを含め、omp の Agent Hub は含めない。omp の COST は 0 でも `$0.0000` と出す。Codex に並列の一覧は無い (2026-09-30)
- [持ち主が毎回 `make up` や `git pull` を打たずに、エージェントの変更を機械へ反映するにはどうするか](2026-09-30-apply-without-the-owner.md) — Linux の standalone home-manager は sudo 不要（公式文書）なので、壁は「誰が pull と switch を起こすか」だけ。macOS は `sudo darwin-rebuild` が nix-darwin の設計で、自動適用の公式機能も無い（PR #1682 が 8 か月止まっている）。comin は nix-darwin を扱えるが standalone home-manager は未対応（#11）。コマンドを絞った NOPASSWD は事実上 root を渡すのと同じ（#165）。自動適用には、OOM で黙って落ちる例と、持ち主の手元の変更を上書きする例があり、どちらも fast-forward のみに限って防いでいる。worktree と拡張の symlink の鮮度に当たる前例は無し (2026-09-30)
- [一枚の 24GB GPU で、複数の 3D モデル生成 AI を切り替えて試す土台は何か](2026-09-30-3d-generation-runtime.md) — 複数の候補を一つの HTTP の口で切り替えられるのは ComfyUI とカスタムノードだけ。ただし代償が二つある。一つは依存の重さで、kijai のラッパーは Windows 向けのビルド済みファイルしか無い（#175）。もう一つは安全性で、Registry のノードパックに RAT が入っていた例がある（#16631、2026-09-29）。モデルごとの公式サーバーは、Hunyuan3D-2.1 だけが非同期の REST API を持ち、TRELLIS.2 は Gradio だけ。候補のライセンス: Step1X-3D は Apache-2.0、TRELLIS.2 と TripoSG は MIT（TripoSG はテクスチャ無し）、Hunyuan3D-2.1 は Tencent のライセンス（29GB 必要）。オープン版の出力はゲーム向けのポリゴン数を大きく超え、四角形の面で作り直す機能は Tencent のクラウドにしか無い。GPU の使い道の切り替えに意味のある名前を付けた前例は無し (2026-09-30)
- [親のモデルは、裏で動く作業役の結果をどう待つのが慣行か](2026-09-30-parent-waiting-on-workers.md) — Claude Code・omp・Codex・pi（durable）の四つとも、既定は「親はターンを終え、完了を合成のメッセージとして差し込んで次のターンを起こす」。そのうえで omp（`wait`）と Codex（`wait_agent`）は、他にすることが無いとき専用の、待つためだけの道具を持ち、説明に「結果は自動で届く、ポーリングするな」と書く。bash の sleep で待つループは Claude Code でも報告があり（#95202、指示を強めても減るだけで消えない）、待つ道具の側にも、タイムアウトの段階で「イベントで待つ」が「ポーリング」に崩れる問題がある（omp #6602）。Swarm には wait が無い (2026-09-30)
