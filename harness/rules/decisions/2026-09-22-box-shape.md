# 容れ物は無人か並列のときだけ使い、複製で入れ、設定は型のファイルで置き、認証情報は入れない

Status: accepted — 実践者は日常を容れ物で回さず、無人時の実例は複製と認証なしに収斂している（2026-09-22）。決定1の「ハーネス自前のサンドボックス」はホストについて2026-09-30-host-claude-without-os-sandbox.mdに置き換えられた

rule: Use containers only for unattended or parallel runs, never as the daily default. Clone the repo into a container (sbx create --clone) rather than mounting a worktree or submounting a subdirectory; render jig config as files/home/ at boot instead of mounting ~/.claude, and inject no credentials except a proxied GitHub token for PRs.
scope: repo

## Problem

エージェントをmicroVMの容れ物(Docker Sandboxes、`sbx`)で動かすときの形を決める。リポジトリをどう入れるか、jigの設定と認証情報をどう入れるか、成果をどう出すか、再開をどう扱うか、ハーネス自前のサンドボックスを中でも動かすか。

## Decision

1. 容れ物は既定にしない。無人で回すときと並列で回すときに使う。日常はhostモード(ハーネス自前のサンドボックス + jigのガード)。
2. リポジトリは複製(`sbx create --clone`)で入れる。同じリポジトリのサブディレクトリを重ねてマウントしない。worktreeを容れ物に渡さない。
3. jigの設定(ガードのルール、AGENTS.md、フックのコード)は型の`files/home/`として起動時に描画して置く。ホストの`~/.claude`などをマウントしない。
4. 認証情報は入れない。PRを出すときだけGitHubのtokenをプロキシ経由で注入する。SSH agentの転送は切る。
5. Claude Codeの自前サンドボックスは容れ物の中でも有効にする(sbxのmicroVMではbubblewrapが非特権で動くことを実測)。CodexはVMの境界に任せる。
6. 成果はgitで取り出す(`sandbox-<名前>` remote、取り出し専用、ポートは起動ごとに変わる)。
7. 再開は容れ物の名前で。同じ名前で再接続して`--continue`。hostと容れ物の間でセッションは引き継がない。

## Alternatives considered

- **容れ物を既定にする**: 名前を挙げて調べた11人に日常的に容れ物を使う人はおらず、Dockerで日常を回した人は画像貼り付け・GPU・速度を理由にOSレベルのサンドボックスに戻った。Anthropicの線引きは「`--dangerously-skip-permissions`のときは容れ物かVM」。却下。
- **作業ツリーを直接マウントする**: 対話用の形で、macOSのvirtiofsにデータ破損の報告が集中(sbx #526「`cp`でNULだけのファイルができた」、#266、#539)。無人や並列の実例は全部、複製かworktree。却下。
- **worktreeを容れ物に渡す**: sbxの文書に「`.git`を辿れずcommitもbranchもできない」と明記、親ディレクトリ経由で秘密ファイルが読めた報告(#154)。動く前例なし。却下。
- **複製の上にサブディレクトリを重ねてマウントする**: 起動が永久に止まる(切り分け済み、v0.43.0)。却下。
- **ホストの`~/.claude`を丸ごとマウントする**: DockerのFAQ「取り込まない、symlinkは追えない」、`~/.claude:ro`はホストの絶対パスに置かれ`/home/agent`から見えない(#113)。sbx自身の型も履歴のサブディレクトリだけをボリュームにする。却下。
- **`~/.ssh`や本物の認証ファイルを入れる**: Anthropic自身の試験で「25回中24回で`~/.aws/credentials`が流出」。漏洩の報告がないのはプロキシ方式か「入れない」方式だけ。却下。
- **中ではyoloにする(Dockerの型の既定)**: Anthropicは「分類器は操作ごとの制御で隔離境界ではない、無人なら隔離境界がなお効く」と重ねる側。Docker #47の利用者の指摘「容れ物の中で履歴を書き換えられれば、ホストで`make build`した時点でサンドボックスは無関係」。却下。
- **hostと容れ物でセッションを引き継ぐ**: どの道具にも前例がなく、worktreeでさえ履歴がパスに紐づいて迷子になる(claude-code #91822)。却下。

## Consequences

- 複製の読み取り専用の元(`/run/sandbox/source`)には未追跡ファイルも見えるので、`.env`などの秘密は網の方針でしか守れない(#260)。
- sbxの複製は取り出し専用で押し込めない(#367)。中に何かを渡し直すときは作り直す。
- Docker SandboxesはLinuxで失敗の報告が多く、閉源でloginが必須。前例が薄い箇所: piとDSHとompの公式agentがない(communityのtemplateのみ)、五つのハーネスを一つの方針で容れ物に入れる道具はdeva(13星)だけ、容れ物の設定時間・コスト・事故率の測定は誰も出していない。
- 対話式の入口(`jig`)が「新規か再開か」の分岐で容れ物の一覧を出し、名前はjigがリポジトリとブランチから付ける。名前は読みやすさのためで同一性の根拠ではなく、一覧・再開・取り出しは`sbx ls --json`のworkspaceとリポジトリの実パスで突き合わせる(basenameが同じ別リポジトリと衝突するため)。
- sbxの組み込み型はentrypointが`claude --dangerously-skip-permissions`、`codex --dangerously-bypass-approvals-and-sandbox`で(バイナリから確認)、設定ファイルでは覆せない。jigの型はmixinではなく`kind: sandbox` + `extends: claude|codex`のforkにしてentrypointを`--permission-mode auto` / `--approve-for-me`に置き換える(Dockerのkit-examples「Fork an existing agent」の形)。ガードのdeny自体はbypassでも効く(Claude Codeのhooks文書)。
- 型の`setup.startup`はエージェントの起動を待たない(切り離されたdispatcherが流す。sbx自身の型のコメントに「installで登録して競合を閉じる」と明記)。ガードの登録や設定の書き換えは`setup.install`に置く。実測: startupに置くと`sbx create`が返った直後の検査でフック未登録、installに移して登録済み。`npm install -g`のbinはフックの素のPATHに無いので`/usr/local/bin`にsymlinkする。
- `extends`で親のsetupは置き換えでなくマージされ、順序は「親install → 子install → 親startup」(実測)。
- SSH agentの転送は起動ごとには切れない。`sbx`の環境から`SSH_AUTH_SOCK`を外しても箱の中に`/run/ssh-agent.sock`が現れる(A/B実測、v0.43.0。転送元はデーモン)。切る手段はマシン全体の`ssh.agentForwardingEnabled`だけなので、jigはそれを触らず、`true`の間は`jig box new`を拒否してコマンドを示す。
