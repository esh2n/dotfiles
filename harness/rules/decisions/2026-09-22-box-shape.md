# 容れ物は無人か並列のときだけ使い、複製で入れ、設定は型のファイルで置き、認証情報は入れない

Status: accepted — 実践者は日常を容れ物で回さず、無人時の実例は複製と認証なしに収斂している（2026-09-22）

rule: Use containers only for unattended or parallel runs, never as the daily default. Clone the repo into a container (sbx create --clone) rather than mounting a worktree or submounting a subdirectory; render jig config as files/home/ at boot instead of mounting ~/.claude, and inject no credentials except a proxied GitHub token for PRs.

## Problem

エージェントを microVM の容れ物(Docker Sandboxes、`sbx`)で動かすときの形を決める。リポジトリをどう入れるか、jig の設定と認証情報をどう入れるか、成果をどう出すか、再開をどう扱うか、ハーネス自前のサンドボックスを中でも動かすか。

## Decision

1. 容れ物は既定にしない。無人で回すときと並列で回すときに使う。日常は host モード(ハーネス自前のサンドボックス + jig のガード)。
2. リポジトリは複製(`sbx create --clone`)で入れる。同じリポジトリのサブディレクトリを重ねてマウントしない。worktree を容れ物に渡さない。
3. jig の設定(ガードのルール、AGENTS.md、フックのコード)は型の `files/home/` として起動時に描画して置く。ホストの `~/.claude` などをマウントしない。
4. 認証情報は入れない。PR を出すときだけ GitHub の token をプロキシ経由で注入する。SSH agent の転送は切る。
5. Claude Code の自前サンドボックスは容れ物の中でも有効にする(sbx の microVM では bubblewrap が非特権で動くことを実測)。Codex は VM の境界に任せる。
6. 成果は git で取り出す(`sandbox-<名前>` remote、取り出し専用、ポートは起動ごとに変わる)。
7. 再開は容れ物の名前で。同じ名前で再接続して `--continue`。host と容れ物の間でセッションは引き継がない。

## Alternatives considered

- **容れ物を既定にする**: 名前を挙げて調べた 11 人に日常的に容れ物を使う人はおらず、Docker で日常を回した人は画像貼り付け・GPU・速度を理由に OS レベルのサンドボックスに戻った。Anthropic の線引きは「`--dangerously-skip-permissions` のときは容れ物か VM」。却下。
- **作業ツリーを直接マウントする**: 対話用の形で、macOS の virtiofs にデータ破損の報告が集中(sbx #526「`cp` で NUL だけのファイルができた」、#266、#539)。無人や並列の実例は全部、複製か worktree。却下。
- **worktree を容れ物に渡す**: sbx の文書に「`.git` を辿れず commit も branch もできない」と明記、親ディレクトリ経由で秘密ファイルが読めた報告(#154)。動く前例なし。却下。
- **複製の上にサブディレクトリを重ねてマウントする**: 起動が永久に止まる(切り分け済み、v0.43.0)。却下。
- **ホストの `~/.claude` を丸ごとマウントする**: Docker の FAQ「取り込まない、symlink は追えない」、`~/.claude:ro` はホストの絶対パスに置かれ `/home/agent` から見えない(#113)。sbx 自身の型も履歴のサブディレクトリだけをボリュームにする。却下。
- **`~/.ssh` や本物の認証ファイルを入れる**: Anthropic 自身の試験で「25 回中 24 回で `~/.aws/credentials` が流出」。漏洩の報告がないのはプロキシ方式か「入れない」方式だけ。却下。
- **中では yolo にする(Docker の型の既定)**: Anthropic は「分類器は操作ごとの制御で隔離境界ではない、無人なら隔離境界がなお効く」と重ねる側。Docker #47 の利用者の指摘「容れ物の中で履歴を書き換えられれば、ホストで `make build` した時点でサンドボックスは無関係」。却下。
- **host と容れ物でセッションを引き継ぐ**: どの道具にも前例がなく、worktree でさえ履歴がパスに紐づいて迷子になる(claude-code #91822)。却下。

## Consequences

- 複製の読み取り専用の元(`/run/sandbox/source`)には未追跡ファイルも見えるので、`.env` などの秘密は網の方針でしか守れない(#260)。
- sbx の複製は取り出し専用で押し込めない(#367)。中に何かを渡し直すときは作り直す。
- Docker Sandboxes は Linux で失敗の報告が多く、閉源で login が必須。前例が薄い箇所: pi と DSH と omp の公式 agent がない(community の template のみ)、五つのハーネスを一つの方針で容れ物に入れる道具は deva(13 星)だけ、容れ物の設定時間・コスト・事故率の測定は誰も出していない。
- 対話式の入口(`jig`)が「新規か再開か」の分岐で容れ物の一覧を出し、名前は jig がリポジトリとブランチから付ける。名前は読みやすさのためで同一性の根拠ではなく、一覧・再開・取り出しは `sbx ls --json` の workspace とリポジトリの実パスで突き合わせる(basename が同じ別リポジトリと衝突するため)。
- sbx の組み込み型は entrypoint が `claude --dangerously-skip-permissions`、`codex --dangerously-bypass-approvals-and-sandbox` で(バイナリから確認)、設定ファイルでは覆せない。jig の型は mixin ではなく `kind: sandbox` + `extends: claude|codex` の fork にして entrypoint を `--permission-mode auto` / `--approve-for-me` に置き換える(Docker の kit-examples「Fork an existing agent」の形)。ガードの deny 自体は bypass でも効く(Claude Code の hooks 文書)。
- 型の `setup.startup` はエージェントの起動を待たない(切り離された dispatcher が流す。sbx 自身の型のコメントに「install で登録して競合を閉じる」と明記)。ガードの登録や設定の書き換えは `setup.install` に置く。実測: startup に置くと `sbx create` が返った直後の検査でフック未登録、install に移して登録済み。`npm install -g` の bin はフックの素の PATH に無いので `/usr/local/bin` に symlink する。
- `extends` で親の setup は置き換えでなくマージされ、順序は「親 install → 子 install → 親 startup」(実測)。
- SSH agent の転送は起動ごとには切れない。`sbx` の環境から `SSH_AUTH_SOCK` を外しても箱の中に `/run/ssh-agent.sock` が現れる(A/B 実測、v0.43.0。転送元はデーモン)。切る手段はマシン全体の `ssh.agentForwardingEnabled` だけなので、jig はそれを触らず、`true` の間は `jig box new` を拒否してコマンドを示す。
