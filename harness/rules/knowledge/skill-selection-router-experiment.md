# スキル選択ルーターの入れ替え実験（A/B'/C）は何を測り、何を測れなかったか

確認日: 2026-09-23

## 答え

スキル選択ルーター（プロンプトに応じてどのスキルの手順を読ませるか判定する仕組み）の改善案を比較するため、実運用のセッション記録から200件のプロンプトを抽出し、正解ラベルを付けたテストセットを作った上で、現行の判定方式（bool 型の一問一答×54スキル）と3つの代替表現（英語版、選択式の日本語版・英語版）をオフラインで比較した。プロンプト本文そのものは記録から意図的に除去されており、この記録には手順・件数・結果の数値のみが残る。

結果、4つの言い回しのどれも他を統計的に上回らなかった（信頼区間が全て重なる）。閾値を上げると見かけの正解率は上がるが、これは「スキルが要らない」という多数派（63.5%）に対する棄権が当たっているだけで、実際にスキルが必要な行のみで見ると閾値を上げるほど正解率が下がるという逆の効果が観測された。選択式（choice）の言い回しは bool 型より較正（確信度と実際の正解率の一致）が明確に良かったが、選択式は上位3件の確率分布をシステムの配線上取得できず、昇格判定に必要な top-3 精度そのものが測定不能だった。閾値0.6ではモデルの答え自体は安定していても、閾値の境界に候補が集まりやすく、同じ入力を5回繰り返すと注入されるスキル集合が17.5%の割合で変わる不安定性が見つかった。

実験の目的だった「新方式が旧方式を上回るか」を判定する昇格ルールは、3条件のうち1つが原理的に計算不能（旧方式のオフライン基準値を作ろうとすると必ず自己言及になる）、1つがオンライン計測でしか測れない（追従率）ため、判定は「未決定」で終わった。何が残っているかというと、選択式のワイヤー配線を直して確率分布を取れるようにすること、そして実際にどれかの案を有効にして追従率と品質をオンラインで測ることの2つ。

## 根拠

- テストセットの構成（4,882セッションファイル・7,406ターンから200件を層別抽出、除外層2種で全体の32%相当を機械的な非人間発話として除去） — `harness/rules/research/skill-selection-experiment/README.md`
- ラベルの内訳（自然開封27件・モデル付与173件、易71/中77/難52、63.5%が「スキル不要」） — `harness/rules/research/skill-selection-experiment/stats.json`
- 4言い回しの正解率がすべて信頼区間で重複、閾値を上げると全体正解率は上がるがスキル該当行の正解率は下がる — `harness/rules/research/skill-selection-experiment/RESULTS-OFFLINE.md` §2
- 選択式の較正の良さ（Brier/ECE）と、確率分布が配線上取得できず top-3 精度が測定不能である欠落 — 同ファイル §1.3・§4
- 閾値0.6での不安定性（5回再実行で注入集合が17.5%変化） — 同ファイル §5
- 昇格ルールの3条件のうち1つが自己言及で計算不能、1つがオンライン限定のため判定「未決定」 — 同ファイル §8
- 凍結時の抜き取り検証（30件中4件がラベル訂正、3.5%以内） — `harness/rules/research/skill-selection-experiment/FROZEN.md`

## 注意点

- どの実行方式（A/B'/C）も実際には有効化されておらず、この記録の数値は「判定モデルが200件にどう答えたか」の測定であって、ルーター運用そのものの効果測定ではない。
- pi 由来のプロンプトは33件のみで、ハーネス単位の結論は支えられない。
- 54件のうち35件のスキルはテストセットに一度も例が無く、それらについての精度は何も言えない。
- 選択式の言い回しは選択肢の並び順を入れ替えると正解率が2.5〜10ポイント動く順序効果が見つかっており、原因は未解明のまま。
- 判定に使った本文は400字に丸めた抜粋で、本番が実際に送る全文とは異なる。
