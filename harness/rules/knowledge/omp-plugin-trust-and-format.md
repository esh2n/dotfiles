# omp（oh-my-pi）のプラグイン機構は何を配布でき、信頼モデルはどうなっているか

確認日: 2026-09-24

## 答え

ompのプラグイン機構は実在し、skills・commands・agents・rules・hooks・tools・MCP・LSPサーバーを一つのディレクトリにまとめて配布できる、単発の拡張ファイルより広い単位である。Claude Codeのプラグインレジストリ形式（`.claude-plugin/marketplace.json`）と互換になるよう意図的に設計されているが、完全互換ではなく相互運用バグが複数報告されている。決定的に重要な点として、プラグインコードはインストールした時点でサンドボックスなしに信頼済みコードとしてメインプロセス内で実行される——署名や第三者レビューの仕組みはない。マーケットプレイスは既定で空で、omp自身が公式のプリセット済みカタログを持つわけではない。エコシステムは活発だが未成熟で、採用実績で「業界標準」と呼べるプラグインは今のところ存在しない（最大でも数十スター規模）。サブエージェント・メモリ・コスト表示はompのコア機能であり、プラグインで埋めるべき「欠けている能力」ではない。

## 根拠

- `docs/marketplace.md`（`can1357/oh-my-pi`リポジトリのrawファイル、直接取得）: 「プラグインはskills・commands・agents・rules・hooks・tools・MCPサーバー・LSPサーバーを含むディレクトリである」「マーケットプレイスシステムはClaude Codeのプラグインレジストリ形式と互換」。
- 使い捨て環境での実行確認: 素の`HOME`では`omp plugin marketplace|discover|list`はすべて空を返し、ユーザーが自分でマーケットプレイスを追加するまで何も見えない。
- `docs/plugin-manager-installer-plumbing.md`（直接取得）: 「プラグインコードはカスタムツールモジュールのインポート時にインプロセスで実行される、サンドボックスなし」「インストールされた時点でプラグインパッケージは信頼済みコードとなる」。
- Claude Code互換の実装バグの実例（GitHub issue検索、直接取得）: `.mcp.json`の`timeout`の単位不一致（Claude Codeは秒、OMPはミリ秒として読む、#12485）、マーケットプレイス経由の`agents/`が`enabledProviders`未設定だと発見されない（#11362）。
- セキュリティissue #12999（open, 直接取得）: 「secretとマークされたプラグイン設定が平文で保存され、ロックファイルがworld-readableになりうる」。
- 更新通知モード`notify`は実際にはユーザー向け通知を出さずdebug logにのみ記録される、とドキュメント自身が明記している。
- GitHubトピック検索（`topic:omp-plugin`、直接取得、総数60件）: 最大スター数は数十件規模（最大で約68）で、ほとんどが1桁台。デファクトの定番プラグインは形成されていない。
- README・`docs/memory.md`・`docs/agent-hub.md`（直接取得）: サブエージェントのオーケストレーション、メモリバックエンド（off/local/hindsight/mnemopi/sharpshooterの5種、既定off）、サブエージェントごとのコスト・所要時間表示は、いずれもプラグインではなくomp本体のコア機能として最初から実装されている。

## 注意点

- GitHub Code Search APIはこの調査の認証状況では利用できず、`.omp-plugin/marketplace.json`を持つリポジトリの網羅的な横断検索はできていない——トピック検索とキーワード検索の範囲に限られる。
- プラグインの実利用規模はGitHubスター数のみに基づく近似値であり、npm経由インストール数などの直接的な利用統計は取得していない。
- 独立したセキュリティ監査の報告は見つからなかった。
- hookが承認ティアシステムより「強い」かどうかはドキュメントのフロー図からの推論であり、明示的な優先順位の記述ではない。
